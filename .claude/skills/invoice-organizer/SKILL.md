# 辨識整理發票

四個步驟：**辨識 PDF → 整理成表 → 檢查統一編號 → 核對金額**，最後交付 Excel 並回報。

腳本：`.claude/skills/invoice-organizer/scripts/check_invoices.py`（以下簡稱「腳本」）。

---

## 步驟一：辨識 PDF

用 Read 分批讀 PDF（例如 `pages: "1-3"`，一次最多 20 頁）。一頁常拼貼 2～4 張發票，每張都要記下，讀完全部頁數再進行下一步。

每張發票要讀出：

| 欄位 | 說明 |
|---|---|
| 發票日期 | 一律轉成西元 `YYYY-MM-DD`（民國年 + 1911，115 年 = 2026 年） |
| 發票號碼 | 2 碼英文字軌 + 8 碼數字，例如 `EC21315831` |
| 發票類型 | `電子發票`、`三聯式(手開)`、`收銀機三聯式` |
| 賣方名稱、賣方統編 | 以印章或列印文字為準 |
| 買方統編 | 用來確認是開給本公司的發票 |
| 品項 | 品名、數量、單位、單價、金額（每一行都記） |
| 銷售額、營業稅、總計 | 照票面數字，不要自己改 |
| 備註 | PO 號、客戶編號等票面備註 |

各類發票的辨識要點：
- **電子發票證明聯**：都是列印字，最清楚。賣方資料在右下角「賣方／統一編號／地址」。
- **三聯式手開發票**：品名與金額是手寫，賣方資料在藍色「統一發票專用章」印章裡（名稱、統編、電話、負責人、地址）。手寫數字看不清楚時，用以下方式交叉推算：
  - 「總計新臺幣（中文大寫）」那一行，例如「壹萬肆仟玖佰叁拾壹元」= 14,931
  - 數量 × 單價 ≈ 金額
  - 銷售額 × 5% ≈ 營業稅
- **收銀機發票**：賣方名稱在上方，統編可能寫成「統一編號」、「NO:」或「#」開頭的 8 碼數字。

**名稱容易看錯**：印章上的字形相近（例如「寓／萬」、「星／晟」、「聖／呈」、「豪／嘉」、「驥／頡」），先照看到的寫，步驟三會用統編反查改正。看不清楚的欄位寫進 `note`，例如「品名為手寫，請核對」。

## 步驟二：整理成表

把辨識結果寫成 JSON，存到 scratchpad（例如 `invoices.json`）：

```json
{
  "buyer_name": "志瑞螺絲企業有限公司",
  "buyer_id": "25095094",
  "period": "115年9-10月份",
  "tax_rate": 0.05,
  "invoices": [
    {
      "date": "2026-10-06", "number": "EC21315831", "type": "三聯式(手開)",
      "seller_name": "新益華司工業社", "seller_id": "08366136",
      "buyer_id": "25095094",
      "sales": 14220, "tax": 711, "total": 14931, "tax_kind": "應稅",
      "items": [{"name": "華司", "qty": 284.4, "unit": "KG", "price": 50, "amount": 14220}],
      "note": "品名為手寫，請核對"
    }
  ]
}
```

- `buyer_name`、`buyer_id` 填本公司（發票上的「買方／買受人」）。
- 沒有單價的品項（例如「1批」、只寫金額的運費），`price` 填 `null`；沒有數量就填 `null`。
- `tax_kind` 填 `應稅`、`零稅率` 或 `免稅`；非應稅的發票不檢查 5%。

腳本輸出的 Excel 第一個分頁「發票總表」，欄位固定為：

**序號｜發票日期｜發票號碼｜發票類型｜賣方名稱｜賣方統編｜品名摘要｜銷售額｜營業稅｜總計｜備註**

- 依發票日期排序，序號從 1 開始。
- 品名摘要：該張發票的品名用「、」串接（重複的只列一次）。
- 總計欄是公式「銷售額 + 營業稅」，最後一列是合計。
- 另有「品項明細」分頁，每個品項一列。

## 步驟三：檢查統一編號

執行腳本：

```bash
python3 -I .claude/skills/invoice-organizer/scripts/check_invoices.py invoices.json 輸出.xlsx
```

腳本對每個賣方統編做以下檢查：
1. **檢查碼**：台灣統編的加權檢查碼。不通過，通常是看錯一個數字，要回原圖重看。
2. **經濟部商工登記**：用 `data.gcis.nat.gov.tw` 開放 API 查公司、商業（行號、企業社）、分公司的登記名稱、狀態、地址，並和發票上的名稱比對。
3. **買方統編**：每張發票的 `buyer_id` 要等於本公司統編。

結果寫在 Excel 的「統編查核」分頁。處理方式：
- **名稱不符**：回原圖確認。字形相近、是自己看錯的，把 JSON 的 `seller_name` 改成登記名稱後重跑腳本；發票本身真的寫了別的名稱，就保留原樣並在 `note` 說明。
- **查無登記**：「○○營業所」這類通常是財政部的稅籍統編，不在經濟部資料內，屬正常情況，回報時註明即可。
- **登記狀態不是「核准設立」**（例如解散、歇業）：一定要在回報中提醒使用者。

連線被擋時（`CONNECT tunnel failed, response 403`）：在雲端環境先用 `get_environment` 查看，再用 `update_environment` 把 `data.gcis.nat.gov.tw` 加入允許的網站；無法加入時，加上 `--no-lookup` 參數執行，並告訴使用者統編沒有上網核對。

## 步驟四：核對金額

同一次執行，腳本會檢查每張發票：
1. 銷售額 + 營業稅 = 總計
2. 營業稅 = 銷售額 × 5%（四捨五入；零稅率、免稅除外）
3. 每個品項的數量 × 單價 ≈ 金額（誤差 1 元以內）
4. 品項金額加總 = 銷售額
5. 發票號碼沒有重複

有問題的發票會在「發票總表」標紅，所有問題列在「檢查結果」分頁。腳本也會在終端印出 JSON（張數、合計、`problems` 問題清單、`registry` 登記資料）。

遇到不符時，先回原圖確認是不是自己抄錯：抄錯就改 JSON 重跑；確定是發票本身的錯，就保留原值，並在回報中指出。重跑到剩下的問題都已確認或說明為止。

## 交付與回報

1. 若有 xlsx skill，執行它的 `scripts/recalc.py 輸出.xlsx`，讓公式帶出數值（沒有也可以，Excel 開啟時會自動計算）。
2. 用 SendUserFile 把 Excel 傳給使用者。
3. 回報時先講結論，再列細節：
   - 共幾張發票，銷售額、營業稅、總計的合計
   - 金額有問題的發票（發票號碼＋說明），沒有就寫「金額全部相符」
   - 依統編更正名稱的賣方（原本看成 → 登記名稱）
   - 無法核對的統編與原因
   - 手寫不清、仍需對照原件的欄位
