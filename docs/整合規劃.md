# 志瑞螺絲：進銷存 × 作業平台 整合規劃

> 評估依據：2026-11-09 上傳的「志瑞螺絲作業平台」資料夾（含進銷存、作業平台多頁版／單檔版、共用資料夾裡的全部資料與備份）。

## 一、現況

### 1. 兩套系統都是「純瀏覽器程式」

| | 志瑞進銷存 | 志瑞螺絲作業平台 |
|---|---|---|
| 檔案 | `志瑞進銷存.html`（單檔，約 3,300 行） | `pages/*.html` 9 個工具 ＋ `zhirui-platform-single.html` 單檔版 |
| 功能 | 總覽、銷貨、進貨、庫存、報價／詢價、標籤、傳真紀錄、收付款、報表、基本資料 | 螺絲查價、發票作業、訂貨排程、螺絲圖面、應收帳款、應付帳款、支票開立、支票登記 |
| 資料放哪 | 瀏覽器 IndexedDB；可「連結共用資料夾」存成 `erp-*.json`、`erp-packs-*.json` | 每個工具一個 localStorage key；可「連結共用資料夾」存成 `<key>.json` |
| 多台電腦同步 | 每 4 秒掃描共用資料夾，以 `_t` 時間戳較新者為準 | 每 3 秒掃描共用資料夾，整個檔案以較晚存檔者為準，被蓋掉的另存「衝突備份」 |

### 3. 兩套系統目前怎麼「勾在一起」

全部靠共用資料夾裡的檔案，而且都是單向、手動：

1. 進銷存「進貨 → 送待開票」：直接改寫作業平台的 `payables.v1.json`。
2. 進銷存「報表 → 作業平台對帳」：讀 `receivables.v1.json`，用客戶簡稱對應，沖銷應收。
3. 進銷存「成本估算」：要選 `pricing.html` 檔案把查價牌價匯進來（存成 pricing packs）。
4. 作業平台 `pages/pricing.html` ＝ 本 repo 的 `readonly.html` 加上「折數管理」；內建牌價資料完全相同。

### 4. 現況的問題

**資料層**
- 兩套系統、十個工具，各自一份資料，靠「掃資料夾」同步。兩台同時改同一個工具就會互相覆蓋（資料夾裡已經有 12 個衝突備份檔）。
- 同步只在 Chrome／Edge 可用，瀏覽器重開要再點一次授權；頁面沒開就不同步、不備份。
- 單檔版和多頁版資料互不相通。
- 同一家客戶在四個地方各存一份：進銷存客戶（有編號）、應收帳款（簡稱）、發票作業（統編）、支票登記（名稱）。供應商也一樣（進銷存、應付帳款、訂貨排程、支票開立）。目前用簡稱比對：應收 108 家只對得上 93 家、應付 119 家只對得上 92 家、發票客戶 349 家只對得上 157 家；有錯字造成的重複（鉑美／铂美、亞曼帝／亞曼蒂）。
- 查價牌價在進銷存裡是副本，牌價或折數改了要手動重匯。

**流程層（一件事要在兩三個地方各填一次）**
- 銷貨：進銷存開銷貨單 → 作業平台另外開發票 → 月底在應收帳款手填每家金額 → 收到支票在支票登記再填一次。
- 進貨：進銷存進貨單 → 送待開票（只能一家一家送）→ 應付帳款 → 支票開立再填一次。
- 向廠商訂製：訂貨排程（作業平台）和採購單（進銷存）是兩套，沒有關聯。
- 報價：查價系統組好的報價單無法變成進銷存的報價單／銷貨單。

## 二、整合目標

1. **一個資料庫、一台伺服器**：公司 Windows 電腦跑伺服器，所有電腦、手機用瀏覽器開 `http://伺服器:8080`，看到同一份資料，改了立刻同步，不再有衝突備份、不再需要選資料夾。
2. **一份主檔**：客戶、供應商、商品、牌價只有一份，所有工具共用。
3. **流程串起來**：銷貨單 → 發票 → 應收 → 支票；進貨單 → 應付 → 支票；查價報價單 → 進銷存報價單 → 銷貨單；訂貨排程 ↔ 採購單。
4. **備份不靠瀏覽器**：伺服器自己每天備份到 C:\backup（或 BeeStation），不必有人開著網頁。
5. **帳號與權限**：登入後才能用；進銷存現有的「管理者／一般人員」延伸到全平台。
6. **現有畫面與操作習慣盡量不變**：兩套都是寫好且在用的介面，整合的是資料和流程，不是重做畫面。

## 三、技術方案

### 伺服器
- **Python 3（只用標準函式庫）＋ SQLite**：不需要安裝任何套件，Windows 上放一個資料夾就能跑；SQLite 單檔資料庫，備份就是複製檔案。
- 提供：靜態網頁（兩套系統的 HTML）、JSON API、即時變更推送（long-polling，各電腦 1～2 秒內看到別人的修改）、登入／權限、每日自動備份、匯入舊資料。
- 用 Windows「工作排程器」開機自動啟動（或 NSSM 做成服務）；固定 IP；防火牆開 8080。
- 外部連線（業務在外、手機）：第二階段再加 Tailscale 或 Cloudflare Tunnel，不直接把 8080 開到網際網路。

### 前端改法：換掉「儲存層」，畫面不動
- 進銷存已經把資料存取包成 `LocalDB`／`LQuery`（類 Firestore 介面：collection/doc/get/set/update/delete/onSnapshot）。新增 `ServerDB` 實作同一個介面改走 API，其餘三千多行畫面程式不用改。
- 作業平台 9 個工具都靠 `localStorage` 一個 key。把外框裡的「共用資料夾同步」模組換成「伺服器同步」模組（同樣的 KEYS 表，push／pull 改走 API，衝突以伺服器版本號判斷），工具本身不用改。
- 這一步做完，就已經解決同步、衝突、備份、瀏覽器限制的問題；之後整合流程時再逐步把工具改成讀共用主檔。

### 資料庫（SQLite）
```
users            帳號、密碼雜湊、角色（admin / staff）
contacts         客戶／供應商（來自進銷存 contacts；加 aliases 欄位放各工具用過的簡稱）
goods            商品
warehouses, accounts
bills, bill_lines 進銷存單據（新單據）
hist_bills       舊系統歷史單據（唯讀，約 45,000 張，另表避免拖慢）
pricing_items    查價牌價（取代 index.html 內嵌 JSON 與進銷存 packs）
pricing_discounts 折數（查價「折數管理」）
kv               作業平台各工具的 JSON（第一階段先原樣存；之後逐步拆成資料表）
   invoices, receivables, payables, checks_out, checks_in, orders, drawings
changes          變更紀錄（版本號，供即時同步與操作日誌）
```

## 四、分階段

### 第 0 階段：伺服器上線（先把資料集中、同步問題解掉）
1. 伺服器程式：靜態檔、API、long-polling、登入、每日備份、開機啟動腳本、安裝說明（Windows）。
2. 進銷存：`ServerDB` 取代 `LocalDB`；拿掉「連結共用資料夾」。
3. 作業平台：伺服器同步模組取代共用資料夾同步；單檔版與多頁版合併（都從伺服器開，資料同一份）。
4. 匯入工具：讀共用資料夾的 `erp-*.json`、`erp-packs-*.json`、`<key>.json`，一次匯進 SQLite；可重複執行（正式切換當天用 BeeStation 上最新資料再跑一次）。
5. 查價牌價改由伺服器提供：`index.html`／`readonly.html` 不再內嵌 4MB JSON，進銷存成本估算直接讀同一份，不用再匯入。

交付：伺服器資料夾（含啟動 `.bat`）、安裝步驟、兩套系統「伺服器版」。
驗收：兩台電腦同時開單互相立即看到；關掉所有瀏覽器仍會備份；手機可用。

### 第 1 階段：主檔統一
1. 客戶／供應商以進銷存 contacts 為唯一主檔，加「別名」欄位；用現有簡稱＋人工確認表把應收、應付、發票、支票、訂貨排程裡的名稱對到 contacts（對不上的列成清單讓你勾選）。
2. 發票客戶的統編（349 家）回填到 contacts。
3. 作業平台各工具的「客戶／廠商」欄位改成從主檔挑選（可打簡稱搜尋），不再各自維護名單。
4. 商品、牌價：查價系統「折數管理」改成寫伺服器；牌價匯入只需做一次，所有人同步看到。

### 第 2 階段：流程串接
1. **銷貨 → 發票**：銷貨單按一鍵開立發票（帶入客戶統編、品項、金額、5% 稅），發票號碼寫回銷貨單。
2. **銷貨 → 應收**：應收帳款每月各客戶金額改由銷貨單自動彙總（保留手動調整與「門市收入」），不必再手填；沖銷用收款單。
3. **收到客票 → 收款**：支票登記新增客票時可勾選沖哪幾筆應收；兌現後自動產生收款單。
4. **進貨 → 應付 → 開票**：「送待開票」改成整月一次全部廠商；應付填開票金額時直接產生「支票開立」的票；列印後產生付款單。
5. **查價報價單 → 進銷存**：查價組好的報價單一鍵轉成進銷存報價單；成交轉銷貨單（商品若不在主檔，自動建立）。
6. **訂貨排程 ↔ 採購單**：採購單建立時自動出現在訂貨排程；排程勾到「完成」提醒開進貨單。

### 第 3 階段：單一入口與權限、外部連線
1. 作業平台總覽成為唯一首頁，進銷存變成其中一個模組（平台外框本來就支援 iframe 模式）。
2. 權限：管理者（全部）、業務（查價、報價、銷貨、發票、訂貨、圖面）、會計（應收應付、支票、收付款、報表）、倉管（進貨、庫存、標籤）。
3. 外部連線（Tailscale／Cloudflare Tunnel）與 HTTPS。
4. 操作日誌、資料匯出（Excel）全平台統一。

## 五、風險與注意事項

- **切換當天**：正式上線前先凍結 1 小時，從 BeeStation 最新資料匯入，核對筆數（商品、客戶、單據、支票）後再讓大家改用新網址；共用資料夾保留不刪，可隨時退回舊版。
- **伺服器電腦**：需固定 IP、不休眠、UPS 更好；SQLite 放在本機硬碟（不要放網路磁碟）；備份另存到 BeeStation。
- **歷史單據品質**：舊系統有錯誤日期（1899、1954）、沒單位的單價（每百支／每千支）等，進銷存已有修正工具；整合時只搬資料不改內容，另列報表供清理。
- **名稱對應**：約 15% 客戶／25% 廠商簡稱對不上，需要人工確認一次（會做成勾選清單）。
- **瀏覽器**：改走伺服器後任何瀏覽器（含 Safari、手機）都能用，不再限 Chrome／Edge。
